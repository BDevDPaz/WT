Contrato formal del Runtime Adapter
1. Objetivo del runtime adapter
El runtime adapter es la capa de infraestructura real que ejecuta IO y efectos externos, mientras que:
• el reducer muta estado canónico,
• los selectors leen estado derivado,
• y el runtime adapter conecta el engine con SQLite, Expo Location, Expo Notifications, Expo Print, MailComposer, Sharing y logging. 1324

───

2. Contrato raíz
2.1 Definición formal
ts
interface WorkTrackerRuntimeAdapter {
  sessionStore: SessionStoreAdapter;
  location: LocationAdapter;
  notifications: NotificationsAdapter;
  reports: ReportsAdapter;
  security: SecurityAdapter;
  logging: LoggingAdapter;
}

2.2 Regla estructural
Cada sub-adapter:
• ejecuta infraestructura real,
• no contiene lógica de negocio de UI,
• no decide el engineState,
• no reemplaza al reducer,
• devuelve datos crudos o resultados de ejecución, para que el effect handler emita eventos secundarios.
Eso es consistente con la separación que ya construimos entre reducer, effect handlers y UI, y con el hecho de que hoy la lógica está repartida entre DB, servicios y UI mock. 1356
